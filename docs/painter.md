# Windows application

## 導入

1. `stream-painter.exe` を任意の場所へ置いて起動する。
2. OBSでブラウザソースを追加する。
3. 設定画面またはタスクトレイの「OBS Browser Source URLをコピー」でURLをコピーし、
   Browser Sourceへ設定する（既定値は `http://127.0.0.1:16873/overlay`）。
4. 幅・高さをOBSの「基本（キャンバス）解像度」と同じ値にする。
5. アプリを起動したまま配信する。

初回起動は設定ファイルを自動作成し、デフォルト値で続行します。公開サーバーへの登録、
トークン発行、ログインは不要です。

対象モニターやOBS連携を変更する場合は、タスクトレイアイコンの「設定...」を開いて保存し、
`stream-painter.exe` を再起動します。

## 操作

- 設定したグローバルホットキー（既定`F9`）: パススルーモードと描画モードを切り替える
- 左ドラッグ: ペン・マーカー・消しゴム・図形を描画
- 左クリック: 選択中のスタンプを配置
- 選択ツール: 最前面の図形／スタンプを選択。枠内ドラッグで移動、四隅で縦横比を保った拡大縮小、
  上側の丸いハンドルで回転。`Escape`で操作を取り消し、空所クリックで選択解除
- 右ボタンを押したまま移動: 内周リングから選択、ペン、マーカー、消しゴム、図形を、外周リング
  から色を選び、ボタンを離して確定。内周の「スタンプ」を通過すると外周がサムネイル付きの
  スタンプリングへ切り替わる
- 動かさずに右クリック: ラジアルメニューを固定し、左右どちらのクリックでも項目を選択
- 固定後に中央をクリック: 従来メニューから全項目と終了を操作
- 円外のコマンドドック: 元に戻す、やり直す、全消去
- 円の右側のレイヤーパネル: レイヤー選択、追加、削除。右端では円の左側へ自動配置
- タスクトレイ: 描画モード切替・Browser Source URLコピー・接続状態確認・設定・
  ログフォルダー・第三者ライセンス・終了

リング中央は「標準メニュー」ボタンを兼ねたデッドゾーンです。最初の右ボタンを中央付近で
離すと固定表示になり、固定後に中央を左または右クリックすると従来メニューが開きます。
固定表示中にリングとドックの外をクリックすると閉じます。右ホールド中にツールリングと
色リングの間まで動かし、候補を選ばずに離した場合も操作をキャンセルします。

コマンドドックは円の下側、画面端に近い場合は上側へ自動配置します。元に戻す／やり直すは
繰り返し操作できるようクリック後も固定表示を維持し、利用できない場合は無効表示になります。
全消去はメニューを閉じ、設定で有効な場合だけ確認画面を表示します。レイヤーパネルは上のレイヤーから表示し、
現在レイヤーを`✓`と背景色で示します。最大8枚で、追加と選択は固定表示を維持します。削除も
確認画面の承認／キャンセル後に固定表示を維持して、成功時は最新の名前・件数・現在レイヤーへ
同期します。最後の1枚は削除できません。全消去の実行直後は「元に戻す」で消去前の
キャンバス全体を復元でき、「やり直す」で再び全消去できます。

スタンプは登録順に8個ずつ、最大4本の同心リングへ配置されます。スタンプ選択中はドックを
一時的に隠し、リング中央へ戻すと色リングとドックへ復帰します。右ホールド操作ではリング
外側まで大きく動かしても、最後の外周で選んだ色またはスタンプをそのまま確定できます。

選択ツールはクリック位置に重なる最前面の図形またはスタンプを選びます。枠内、拡縮ハンドル、
回転ハンドルでは操作に合うカーソルへ変わります。移動と回転後もitem全体をキャンバス内へ収め、
拡縮は中心基準・縦横比固定で最小表示寸法を保ちます。ドラッグ中はWindowsオーバーレイで即時
プレビューしながら、最新transformを16ms間隔（約60fps）でOBSへ同期します。Browser Sourceは
対象より前の履歴をprefixとして一度だけcacheし、対象と後続項目を元の順序で描き直すため、
後から描いた線・図形・スタンプ・消しゴムとの前後関係を保ちつつ履歴全体は毎フレーム再描画しません。ボタンを
離した時点ではタイマーを待たず最終状態を送り、履歴にはドラッグ全体を1回の操作として記録します。
`Escape`、pointer cancel、capture喪失時は開始時のtransformへ戻します。操作後も選択は維持される
ため続けて調整でき、別ツールへの切替または空所クリックで解除します。

Windows Pointer APIでpenとして識別できる入力は、筆圧と傾きをローカル表示・OBS表示の両方へ
反映します。ペンは筆圧で基準幅の20%から100%、マーカーは筆圧で65%から100%になり、さらに
傾きの大きさで最大1.75倍まで太くなります。消しゴムは操作を予測しやすい固定幅です。
マウス、touch、筆圧・傾きを報告しないペンは筆圧100%・傾きなしとして扱うため、従来の一定幅を
維持します。ブラシpresetはストロークへ記録されるので、WindowsオーバーレイとBrowser Sourceが
同じ数式・同じ見た目を使います。
全消去前の確認は既定で有効です。設定で無効にすると確認画面を省略しますが、空のキャンバスでは
設定にかかわらず確認画面を表示しません。全消去後もレイヤーカタログは残します。消しゴムと選択ツールは
現在レイヤーだけを対象にし、Undo／Redoは全レイヤーをまたいだ操作順です。レイヤー削除は所属する
描画だけを消しますが、削除済みレイヤーを復元しないようUndo／Redo履歴も破棄します。そのため
対象レイヤーが空でも履歴がある場合は「元に戻せない」確認を表示し、キャンセル時は何も変更しません。
全消去そのものを1回のUndo／Redo操作として
扱い、復元時は多数の項目を増分送信せず、完全snapshot 1件でBrowser Sourceを再同期します。
メモリを履歴上限内へ保つため、全消去より前の個別Undo履歴は従来どおり破棄し、直近の
全消去前キャンバスだけを復元点として保持します。その後の描画と復元点の合計が通常の項目数・
点数上限を超える場合は、不完全なキャンバスを復元しないよう全消去の復元点全体を失効させます。
図形／スタンプの移動・拡縮・回転も1回の操作としてUndo／Redoできます。Undoした操作はRedoで
戻せます。Undo後に新しく描画、スタンプ配置、またはtransformを行うとRedo履歴は破棄されます。

設定画面の「OBS全画面プロジェクターの表示中だけオーバーレイを有効にする」を有効に
すると、対象モニターにOBS全画面プロジェクターがある間だけ透明オーバーレイを有効に
します。「ホットキーでOBSプロジェクターを自動的に開く」を有効にすると、切替時に
obs-websocket経由でプロジェクターを開くこともできます。接続から画面の表示確認までを5秒以内で
試行し、期限を超えた要求の結果は後から届いても適用しません。再度ホットキーを押すと新しい要求
として安全に再試行できます。

対象モニターでOBS全画面プロジェクターを検出している間は、フォーカスを奪わずに
`StreamPainterのメニュー／設定画面 > StreamPainterオーバーレイ > OBSプロジェクター >
その他のウィンドウ` の表示順を維持します。従来の右クリックメニューやトレイメニューを
開いている間は定期的なZ-order再構成を保留し、閉じた直後にオーバーレイとプロジェクターを
再同期します。リングメニューはオーバーレイ自身に描画するため、常に描画内容より手前です。
StreamPainterがOBSを最前面へ移した場合は、プロジェクターの終了・最小化または
StreamPainterの終了時に元のTopmost状態へ戻します。

## ネイティブ描画性能

Windowsオーバーレイは各ユーザーレイヤーの完成GPU bitmap、描画中ストローク用bitmap、次に描く
確定segment番号を保持します。
各pointer updateでは点列を更新して低優先度の`WM_PAINT`を予約します。Windowsはqueued inputを
paintより先に処理し、同じinvalid regionへの要求も統合するため、連続入力を1回の`Present(1)`へ
集約できます。VSync待ち自体をframe paceとして使うため、16ms timerを重ねて30fps相当へ
落としません。フレーム時は中点法で新たに確定したsegmentだけをbitmapへ追記するため、
1点の更新コストは、それ以前の点数ではなく新規segment数に比例します。ペンとマーカーは不透明な
scratchを最後にstroke opacityで1回合成し、消しゴムは開始時の所属レイヤー複製へ作用するので、
キャンセル時に確定履歴を壊しません。確定時も未処理segmentとtail（またはdot）だけを追加します。
通常frameは最大8枚のbitmapだけを下から上へ合成し、別レイヤーの履歴pathを再生しません。選択中は
対象レイヤーのselected itemより前をprefix bitmapへ保持し、selected itemと同じレイヤーのsuffixだけを
再生してから上下レイヤーcacheの間へ合成します。

目標は60fpsの1フレーム予算である16.67ms未満です。10,000点strokeの9,999点目まで処理済みの
cursorへ最後の1点を追加する計測テストを2,000回平均し、この予算未満であることを検証します。
WindowsではWARP device上のactive bitmapへ最後のDirect2D pathを追記する時間も別に記録し、
cursorが1segmentだけ進むことを確認します（共有CIのwall-clock揺らぎを考慮し、こちらの厳密な
16.67ms判定は純geometry側で行います）。
同じテスト群で、全10,000点を1点ずつ増分生成したgeometryが一括生成結果と一致すること、および
Browser Source側も同じ1-origin cursorと数式で一致することを検証します。

筆圧・傾きについては、platform非依存テストでWindowsの0..1024の筆圧、±90度の傾き、mask欠落、
範囲外値、mouse／touch fallbackを検証し、WindowsのWARP Direct2Dテストで筆圧・傾きに応じて
実描画pixelの被覆面積が変わることを検証します。物理ペンと固有driverを使った確認済み構成は
以下です。

| Windows | Windows 11 Pro `10.0.26200` (build `26200`) |

validatorが自動記録した証拠範囲は、ペン接地中のマーカーストローク2本、筆圧と
X/Y傾きの変化範囲、device/driver/app情報の検証中の一致、config不変です。
この成功記録は、操作者が当該Wacom Intuos Pro Lを検証中に使用したという確認に

入力元deviceを自動断定しません。

#### 操作者による目視・手動確認

validatorの自動判定とは別に、操作者は次の振る舞いを確認しました。

- ペンのhover中は線が表示されず、接地後だけ描画される
- 検証した2本の線がStreamPainter overlayとOBS projectorの両方に表示される
- mouseで従来どおり一定幅の線を描画できる

mouse／touch fallbackは既存のplatform非依存テストで検証し、関連するWARP自動テストでは
筆圧・傾きによる実描画の変化を検証します。この実機runではhoverから接触への遷移と
mouse fallbackを追加で手動確認し、touch fallbackは手動確認に含めていません。
他の構成を追記する場合も、
ペン先からの入力、最小・最大筆圧、X/Y両方向の傾き、hoverから接触への遷移、mouse fallback、
StreamPainter overlayとOBS projectorの表示を確認し、機種名・driver version・Windows versionを
この節へ追記します。

### 物理ペン入力の手動検証

この手順は実行中のStreamPainterへ読み取り専用で接続し、アプリの起動・停止や設定変更は行いません。
あらかじめ通常どおりStreamPainterを起動し、設定画面に表示されるローカルサーバーのポートを確認して
ください。次にPowerShell 5.1またはPowerShell 7でリポジトリ直下から次を実行します。

```powershell
Get-PnpDevice -PresentOnly |
  Where-Object FriendlyName -Match '(?i)(\b(pen|stylus|tablet|digitizer|wacom)\b|pentablet|\u30da\u30f3|\u30bf\u30d6\u30ec\u30c3\u30c8|\u30c7\u30b8\u30bf\u30a4\u30b6)' |
  Select-Object Status, Class, FriendlyName

.\scripts\windows\validate-pen-input.ps1 `
  -Port 16873 `
  -ExpectedDeviceName 'Wacom Intuos Pro L' `
  -PublicDeviceLabel 'Wacom Intuos Pro L'
```

`ExpectedDeviceName`には、その場で実際に使うWindowsのdevice名を正確に指定し、そのdeviceだけを
使います。上の絞り込みに出ない言語や製品名でも、present deviceとのexact matchはvalidatorが確認します。
`PublicDeviceLabel`にはserialや個人名を含まない、共有可能なmodel名を指定
します。接続後にマーカーを選択して、筆圧を弱から強まで変えながらX/Y両方向へ傾けた線を2本以上
描きます。
validatorは接続直後のsnapshotを基準として除外し、その後の新しい`stroke_begin`、`stroke_points`、
`stroke_end`だけを収集します。各線を独立に評価し、2本それぞれが6要素の有限なpoint、マーカー固有の
brush設定、筆圧範囲0.05以上、X傾きの変化範囲0.02以上、Y傾きの変化範囲0.02以上を
満たすと成功します。mouse fallbackとpen 1本の組合せ、不正値、変化量不足は成功として扱いません。
各マーカーストロークの終了時に、完了数／合格数、直近ストロークのpoint数・筆圧範囲・X/Y傾き範囲と
不足している閾値を表示します。制限時間に達した場合も、同じ座標／stroke IDを含まない最終進捗を
timeoutエラーへ含めるため、入力が届かなかった場合と変化量が不足した場合を区別できます。
途中で完全snapshotを受信した場合やrevisionに欠番がある場合は、異なる状態の証拠を混在させず
検証を中断するため、もう一度実行してください。

出力するJSON summaryは座標、初期snapshot、Windowsユーザー名・コンピューター名、device serial、
PnP IDを含みません。OS、操作者が指定してWindows上でpresent/OKと確認できたdeviceの公開用model名・
driver version・provider/service情報、候補件数、実行中exeのSHA-256（埋め込まれていればversion）
と、座標を含まない集計値だけを記録できます。app listenerのhash、指定device、driver情報を取得できない
場合や、それらが検証中に変化した場合は成功にしません。Windowsの入力event自体にはPnP IDを載せない
ため、候補一覧だけから入力元を自動断定せず、操作者が指定したdeviceを実際に使用したことも記録します。
raw device名と候補一覧は成功summaryへ出力しません。検証前後にはWindowsのcanonicalな
`%APPDATA%\StreamPainter\config`にある`config.toml`と`config.toml.bak`のSHA-256を比較し、
どちらかが変化した場合は失敗します。この対象directoryをcommand lineで迂回することはできません。
共有前にsummaryを目視確認してください。現在の確認済み成功は上記構成に限ります。

```console
cargo test --locked --manifest-path painter/Cargo.toml ten_thousand_point -- --nocapture
bun test client/src/Overlay/renderer/geometry.test.ts
```

`Present(1)`のVSync待ち、履歴変更によるbaked再構築、GPU device-lossからの復旧はこの純geometry
計測には含みません。後二者は例外経路として完全履歴を優先し、復旧後に増分cursorを作り直します。

## 設定

タスクトレイアイコンの「設定...」から、次の項目を編集できます。

- OBS Browser Source URL（表示と1クリックコピー）
- ローカルサーバーの到達状態と、OBS Browser Source WebSocketの接続状態
- ローカルサーバーのポート
- 描画対象モニターとキャンバスのアスペクト比
- ローカル描画表示とOBSプロジェクター追従
- OBS WebSocketのURL・パスワード・Program/Preview（パスワードはWindows資格情報へ保存）
- プロジェクターを自動で閉じるか
- 描画モード切替のグローバルホットキー
- 現在のWindowsユーザーでログイン時に自動起動するか
- 標準ブラシ色と幅
- 全消去の前に確認画面を表示するか（既定は有効）
- PNGスタンプの追加・削除・名称・既定表示サイズ・不透明度

ホットキー欄へフォーカスを移して希望するキーの組み合わせを押すと、`Ctrl`、`Alt`、`Shift`、
`Win`を含めてcaptureします。「解除」はホットキー登録を止めてトレイ操作だけにし、
「既定(F9)」は初期値へ戻します。通常入力を全体で奪わないよう、ファンクションキー以外には
修飾キーが必要です。Windowsが予約する`F12`、対応外のキー、同じ修飾キーの重複は拒否します。
旧バージョンで作成した設定にホットキー項目がない場合は、自動的に既定の`F9`を使用します。

Windows自動起動は既定でOFFです。有効にすると、現在のユーザーの
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`に、REG_SZ値
`StreamPainter`として現在のexeの絶対パスだけを登録します。管理者権限は使わず、登録コマンドに
`--settings`、`--detect`などの引数は付けないため、ログイン時は通常の常駐モードで起動します。
Runキーの[260文字上限](https://learn.microsoft.com/windows/win32/setupapi/run-and-runonce-registry-keys)
を超える場所にexeがある場合は、起動できない登録を作らず保存時にエラーを表示します。
StartupフォルダーのショートカットではなくHKCU Runを使うことで、COMによる`.lnk`管理を増やさず、
1つの値から実状態と登録先を検証し、保存失敗時にも元の値を正確に復元できます。
ON/OFFを繰り返して保存しても同じ状態へ収束し、`config.toml`には自動起動フラグを保存しません。
設定画面のチェックと状態表示は、画面を開くたびにこのWindows登録を直接読み取ります。

portable exeを登録後に移動すると、Windowsの登録先は自動では変わりません。移動先のexeを手動で
起動して設定を開くと「修復が必要」と表示されます。チェックをONのまま保存すると現在のexeへ
登録し直し、OFFにして保存すると古い登録を解除します。登録先exeが削除された場合も同様に検出
しますが、実行できるStreamPainterが1つも残っていない場合はアプリ自身を起動できないため、
次のコマンドで手動解除してください。

```powershell
reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v StreamPainter /f
```

レジストリエディターを使う場合も同じキーの`StreamPainter`値だけを削除します。USBメモリなど
ログイン時に存在しない場所のexeを登録すると起動できないため、常時利用できる場所へ置くことを
推奨します。登録値が壊れている、別のexeを指す、または起動引数を含む場合も、設定画面からONで
正常な通常起動登録へ修復するか、OFFで安全に削除できます。

保存前にポート、URL、アスペクト比、ホットキー、ブラシ値を検証します。通常アプリの
タスクトレイから開いた設定画面では、ホットキーとWindows自動起動を保存と同時に反映し、
その他の設定は再起動後に反映します。`--settings`で別processとして開いた場合は、ホットキーも
通常アプリの再起動後に反映しますが、自動起動はその場で反映します。新しいホットキーが他の
アプリと競合した場合は設定画面に通知し、以前のホットキーを維持します。設定ファイルの保存が
失敗した場合も登録を以前の値へ
戻します。自動起動値も設定保存と一緒にtransactionalに変更し、後続処理が失敗した場合は
元のレジストリ型と内容へ戻します。ポートを変えた場合は、画面上部に表示された新しいURLを
OBS Browser Sourceにも設定してください。ローカルサーバーをLANへ公開する設定はありません。

接続診断はHTTPを定期pollingせず、内蔵サーバーの起動・停止とWebSocket sessionの変化を
設定画面へ即時通知します。「ローカルサーバー: 到達可能」と「OBS Browser Source: 未接続」は、
サーバー自体は動いている一方、OBSがまだ接続していない状態です。入力中のポートが実行中の
ポートと異なる場合も表示されるため、表示URLをコピーしてOBS側を更新してください。

設定の保存先は `%APPDATA%\StreamPainter\config\config.toml` ですが、通常は直接編集する必要は
ありません。保存時は書きかけのファイルが残らないように置換し、直前の設定を
`config.toml.bak` に保持します。主ファイルを読み込めない場合は、このバックアップから
自動復旧します。OBS WebSocketパスワードだけは両ファイルへ保存せず、現在のWindowsユーザーの
資格情報マネージャーに Generic credential `StreamPainter/OBS WebSocket` として保存します。
設定画面でパスワード欄を空にして保存すると、この資格情報も削除します。

別途バックアップや移行をする場合は `config.toml` と `config.toml.bak` をコピーできますが、
パスワードはバックアップに含まれません。別PCまたは別のWindowsユーザーへ移した後は設定画面で
パスワードを入力し直してください。exeをUSBメモリ等から起動するportable運用でも、設定と
資格情報の保存先はそれぞれ `%APPDATA%` と現在のWindowsユーザーの資格情報マネージャーであり、
exeと一緒には移動しません。設定ファイルだけを削除・復元しても、既存の保護資格情報は自動削除・
上書きされません。

旧obs-painter版の設定しかない場合は初回起動時に新しい場所へコピーし、元のファイルも
残します。旧版の平文パスワードは資格情報への保存成功後に、新旧それぞれの主ファイルと
`.bak` から除去します。移行途中で失敗した場合は、資格情報または元の平文を残したまま次回起動で
再試行します。以前の版にあった `server_url` と `painter_token` は読み込み時に無視され、
設定画面で保存すると除去されます。

スタンプ画像は設定画面で選択した時点で検証され、アニメーションを含まない静止PNGだけを
`%APPDATA%\StreamPainter\stamps\<id>.png` へコピーします。登録できるのは5 MiB以下、
最大2048×2048 pxかつ1枚4,194,304 px以下のPNGを32個までで、全画像の合計は
16,777,216 px（RGBA展開時に約64 MiB）以下です。元画像を移動・削除しても登録済みスタンプ
には影響しません。削除したスタンプの管理ファイルは次回アプリ起動時に除去されます。

ポート競合などで通常起動できない場合は、次のコマンドで設定画面だけを開けます。

```powershell
stream-painter.exe --settings
```

## トラブルシュート

### OBSが透明なまま

- タスクトレイまたは設定画面で「ローカルサーバー: 到達可能」か確認する。
- 「OBS Browser Source: 未接続」ならURLを1クリックでコピーし、OBS側のURLと照合してから
  Browser Sourceを右クリックして「更新」する。
- 「入力中のURLとは不一致」と表示された場合は、設定を保存してStreamPainterを再起動し、
  新しいURLをOBSへ設定する。
- UIを開けない場合に限り、ブラウザで `http://127.0.0.1:16873/health` を開き、`ok` が返るか
  確認する。

### ポートを使用できない

起動時にエラーが表示されます。別のアプリが同じポートを使用している場合は、
`stream-painter.exe --settings` でポートを変更し、表示されたOBS URLも更新します。
StreamPainterをもう一度起動した場合は多重起動せず、既に起動中であることを通知します。
通常版の実行中でも `--settings` と `--detect` は利用できます。

### ホットキーで描画できない

- 設定画面に表示されたキーを確認する（初期値は`F9`）。
- 他アプリが同じグローバルホットキーを使用していないか確認し、設定画面で別の組み合わせを
  指定する。
- プロジェクター追従が有効な場合、設定対象モニターでOBSプロジェクターを表示する。
- OBS自動制御が有効な場合、OBSのWebSocketサーバー設定とパスワードを確認する。
- Previewを選択している場合、OBSがスタジオモードになっているか確認する。Previewを開けない
  ときにProgramへ自動切替はしないため、意図しない映像が表示されることはありません。

起動時にキーが競合すると前面の警告画面で通知します。StreamPainter自体は終了せず、
タスクトレイの「描画モード切替」から操作できます。競合の詳細はログにも記録されます。

診断用に `stream-painter.exe --detect` を実行すると、モニタ、検出対象ウィンドウ、
OBS判定、Topmost状態を表示します。

通常起動・設定画面・診断モードのログは
`%LOCALAPPDATA%\StreamPainter\logs\stream-painter.YYYY-MM-DD.log` に保存します。日単位で
ローテーションし、直近7ファイルだけを保持します。問題を報告する場合は、再現直後のログを
添付してください。フォルダーはタスクトレイの「ログフォルダー...」から開けます。
OBS WebSocketパスワードやスタンプ画像本体はログへ記録しません。

GPUドライバーの再起動などでDirect2D/DXGIの描画に失敗した場合は、描画資源を破棄し、
保持しているキャンバス履歴から自動復旧を試みます。復旧できない場合はログに詳細を記録し、
2秒以上間隔を空けて再試行します。

実行中に対象モニターの解像度・配置・接続状態が変わった場合は、透明ウィンドウと描画資源を
新しい物理ピクセル領域へ作り直します。設定したモニター番号が見つからない間はプライマリ
モニターへ退避し、次のディスプレイ変更時に再検出します。
